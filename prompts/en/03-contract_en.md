# 03 - CONTRACT: Interface Contract

> **Stage goal**: Confirm "what the new method takes as input, what it outputs, and what happens on failure" to prevent Execution AI from hallucinating field names.
>
> Choose the corresponding branch based on project mode.

## Branch A: Modify Existing Project → CONTRACT

### Execution AI Prompt (send to Window B)

```text
【Stage: CONTRACT】Confirm interface only. Do not write code, do not execute commands.

【New/Modified Module】
- Input: {{your expected input parameters}}
- Output: {{your expected return structure}}
- On failure: {{your expected failure behavior}}

【Existing Data Structure】
- {{data object name}} fields: {{list actual fields found in PROBE}}

Please answer:
1. What are the actual fields of {{related result object}} in your project? List them.
2. What is the output format requirement when calling the external model? (JSON format, field names)
3. If the new logic fails, what's the degradation path? Which old method to call? Are input/output compatible?
4. Will coding modify only one file at a time? Confirm.
5. Does the frontend-backend API change? (if frontend modification is involved)

After confirmation, I'll reply "confirm" to enter coding.
Add [CONTRACT_DONE] at the end of output.
```

```text

Based on the confirmed DESIGN architecture:
{{paste the module dependency graph and data flow from DESIGN stage}}

- {{frontend framework/backend framework/database/other}}

Please answer:
1. 【Data Model Design】What are the core data entities? List each entity's field names, types, and constraints.
2. 【API Interface Design】What interfaces are needed? List each interface's path, method, request parameters, and return structure.
```
