# 04 - CODE：单文件推进

> **阶段目标**：一次只改一个文件，改完一个等你确认再改下一个。
>
> 如果有多个文件要改，重复本阶段（文件1 → 文件2 → ... → 文件N）。

---

## 分支A：改造现有项目 → CODE

### 第1个文件

```text
【阶段：CODE-文件1】只改这一个文件，不要动其他文件。

【绝对铁律】
1. 用户没有说"确认"，绝不进入下一个文件
2. 绝不一次性修改多个文件
3. 每改完一个文件，必须 git add + git commit（提交信息写明改了什么）
4. 如果修改失败，必须 git checkout 回退到上一次提交
5. 禁止 git push --force、git reset --hard 等破坏性操作
6. 禁止一次性 git add . （必须指定具体文件）

{{新建/修改}} 文件：{{文件路径}}

改造目标：{{具体功能描述}}

当前项目上下文（PROBE发现）：
- 模型调用封装在 {{文件}} 的 {{方法}}
- 相关数据结构：{{数据对象}} 字段为 {{字段列表}}
- 旧方法 {{方法名}} 在 {{文件}} 保留备用

要求：
- 只输出变更部分的代码，用注释标明插入位置
- 如果新建文件，输出完整代码
- 关键路径必须加 [PROBE] 日志，格式：logger.info(f"[PROBE] 具体信息")
- 所有异常必须捕获，不能抛未处理异常
- 代码风格与项目现有代码保持一致
- 不要重启服务，不要运行测试，不要读取日志
- 只输出这个文件的代码

输出后加 [FILE_DONE: {{文件名}}]
等待我发"下一步"再继续。
```

### 等待执行AI返回

你会收到代码修改（`[FILE_DONE: 文件名]`）。

把完整返回复制下来。

### 策略AI提示词（发给窗口A）

把 `{{执行AI的代码修改}}` 替换为你复制的内容：

```text
【CODE审查任务】

请审查以下执行AI返回的代码修改。

## 执行AI的代码修改：
{{执行AI的代码修改}}

## 你的任务：

### 第一步：合规性审查
- [ ] 只改了1个文件（输出中只有1个 [FILE_DONE]）
- [ ] 有 [PROBE] 日志（代码中有 logger.info(f"[PROBE] ...") ）
- [ ] 有异常捕获（有 try/except 或类似机制）
- [ ] 引用了PROBE中的方法（如 _call_api）
- [ ] 字段名与CONTRACT一致（没有幻觉字段名）

### 第二步：判断下一步

如果还有下一个文件要改，输出【CODE-文件N】指令。
如果是最后一个文件，输出【VERIFY】指令（见 05-verify.md）。
```

### 循环执行

- 如果策略AI说"还有下一个文件" → 复制【CODE-文件N】指令发给执行AI，重复本阶段
- 如果策略AI说"最后一个文件" → 复制【VERIFY】指令，进入 [05-verify.md](05-verify.md)

## 分支B：从零新建项目 → CODE

### 骨架搭建顺序

从零新建项目必须按以下顺序搭建，每层完成后验证一次：

```text
第1层：配置文件（被所有模块依赖）
第2层：工具类/公共模块（被业务模块依赖）
第3层：入口文件（依赖配置和工具类）
第4层：业务模块（依赖以上所有层）
```

### 第1层：配置文件

```text
【阶段：CODE-骨架-配置层】只创建配置文件，不要动其他文件。

【绝对铁律】
1. 用户没有说"确认"，绝不进入下一层
2. 绝不一次性创建多个层的文件
3. 每创建完一个文件，必须 git add + git commit
4. 禁止 git push --force、git reset --hard
5. 禁止一次性 git add .

已确认的配置清单：
{{粘贴CONTRACT阶段确认的配置文件列表}}

请创建以下配置文件：
- {{配置文件1路径}}：{{用途说明}}
- {{配置文件2路径}}：{{用途说明}}

要求：
- 每个文件输出完整代码
- 配置文件必须有合理的默认值
- 必须有注释说明每个配置项的用途
- 创建完后，验证每个文件能被正常读取/导入

验证方式：{{运行什么命令验证配置文件有效}}

输出后加 [FILE_DONE: {{文件名}}]
每创建完一个文件等待我发"下一步"再继续。
```

### 配置层验证

```text
【阶段：CODE-骨架-配置层验证】验证配置层是否正常工作。

请执行：
1. 导入/读取所有配置文件
2. 验证必填配置项是否都有值
3. 验证配置文件之间没有冲突

如果验证通过，输出 [LAYER_DONE: 配置层]
如果验证失败，输出 [LAYER_FAILED: 配置层] + 失败原因
```

```text

【绝对铁律】（同上）

已确认的工具模块清单：
{{粘贴CONTRACT阶段确认的模块接口列表}}

请创建以下文件：
- {{文件路径}}：{{功能说明}}
- {{文件路径}}：{{功能说明}}

要求：
- 每个文件输出完整代码
- 每个工具模块必须能独立导入（不依赖业务模块）
- 必须有类型标注
- 创建完后，验证每个模块能被正常导入

验证方式：{{运行什么命令验证模块可导入}}

输出后加 [FILE_DONE: {{文件名}}]
每创建完一个文件等待我发"下一步"再继续。
```

### 工具层验证

```text
【阶段：CODE-骨架-工具层验证】验证工具层是否正常工作。

请执行：
1. 导入所有工具模块
2. 验证每个模块的公开接口（函数/类）都能被调用
3. 验证工具模块不依赖业务模块

如果验证通过，输出 [LAYER_DONE: 工具层]
如果验证失败，输出 [LAYER_FAILED: 工具层] + 失败原因
```

### 第3层：入口文件

```text
【阶段：CODE-骨架-入口层】只创建入口文件，不要动其他文件。

【绝对铁律】（同上）
```

```text

1. 运行入口文件
2. 验证启动日志无报错
3. 验证配置和工具模块都被正确加载

如果验证通过，输出 [LAYER_DONE: 入口层]
如果验证失败，输出 [LAYER_FAILED: 入口层] + 失败原因
```

```text

【绝对铁律】
1. 用户没有说"确认"，绝不进入下一个文件
2. 绝不一次性创建多个文件
3. 每创建完一个文件，必须 git add + git commit
4. 禁止 git push --force、git reset --hard
5. 禁止一次性 git add .

已确认的业务模块清单：
{{粘贴CONTRACT阶段确认的API接口和数据模型}}

- {{文件路径}}：{{功能说明}}

要求：
- 每个文件输出完整代码
- 必须导入配置层和工具层的模块
- 必须实现CONTRACT阶段定义的接口
- 所有异常必须按CONTRACT阶段定义的策略处理
```

