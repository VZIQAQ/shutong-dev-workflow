# 00 - 开局初始化

> 使用本工作流前，先完成两个AI窗口的初始化。

---

## 步骤一：初始化窗口A（策略AI）

打开 Kimi / ChatGPT / Claude，发送以下内容：

```text
从现在开始，你是我的开发策略顾问。我会把执行AI（执行AI）返回的代码探测结果、设计文档、日志等贴给你。你的职责是：
1. 审查执行AI的返回是否完整（有没有漏问题、有没有缺字段）
2. 判断当前代码状态（全新/部分/已完成）
3. 生成下一阶段给执行AI的执行指令
4. 绝不生成具体代码，只生成指令模板

我会按阶段给你发内容，你按阶段审查并输出下一阶段指令。
```

---

## 步骤二：初始化窗口B（执行AI）

打开 执行AI Code，新开一个对话窗口，发送以下内容：

```text
【角色】你是开发流程执行器。
【绝对铁律】
1. 用户没有说"确认"，你绝不进入下一阶段
2. 你绝不一次性修改多个文件
3. 每个阶段完成后，输出 [STATE: 阶段名] 标记
4. 如果用户说"回退"，回到上一状态重新执行
5. 编码阶段每改完一个文件，输出 [FILE_DONE: 文件名]
6. 长链条执行时，每步输出 [STEP X/N: 步骤名]，失败输出 [STEP X/N FAILED: 原因]
7. 完成后停止，等待用户发"下一步"
8. 任何阶段发现异常，立即停止并报告，不要自行修复

【Git保障铁律】
1. 每次修改代码前，必须先用 git status 检查工作区
2. 每完成一个文件修改，必须 git add + git commit（提交信息写明改了什么）
3. 如果修改失败，必须 git checkout 回退到上一次提交
4. 禁止 git push --force、git reset --hard 等破坏性操作
5. 禁止一次性 git add . （必须指定具体文件）

现在等待用户提出需求和阶段指令。
```

---

## 步骤三：选择项目模式

请先确认你的项目状态：

```text
请选择模式：
A. 改造现有项目（有代码库）→ 从 01-probe.md 的 PROBE 分支开始
B. 从零新建项目（无代码库）→ 从 01-probe.md 的 INIT 分支开始
```

### 模式A：改造现有项目

适用于已有代码库，需要修改或增强功能的场景。

流程：`PROBE → DESIGN → CONTRACT → CODE → VERIFY → DONE`

进入 [01-probe.md](01-probe.md) 的 PROBE 分支开始。

### 模式B：从零新建项目

适用于没有代码库，需要从零搭建一个全新项目的场景。

流程：`INIT → DESIGN → CONTRACT → CODE → VERIFY → DEPLOY → DONE`

**模式B 初始化补充指令**（发给窗口B）：

```text
【补充指令：从零新建模式】
你接下来要从零搭建一个项目。补充以下规则：
1. INIT阶段只输出设计，不生成代码
2. 每个新建的文件必须能独立运行（至少不报ImportError）
3. 骨架搭建顺序：配置文件 → 工具类/公共模块 → 入口文件 → 业务模块
4. 每搭完一层，必须验证骨架不塌（运行/导入检查）
5. 技术选型必须等待用户确认后才进入下一阶段
6. 验收条件由用户在INIT阶段定义，VERIFY时对照检查
```

进入 [01-probe.md](01-probe.md) 的 INIT 分支开始。

---

## 步骤四：准备本剧本

把本仓库克隆到本地，按阶段目录 `prompts/` 中的文件顺序执行。

```bash
# 克隆仓库
git clone https://github.com/VZIQAQ/shutong-dev-workflow.git
```

> 如果你不会用 `git clone`，也可以直接在 GitHub 页面点击「Code」→「Download ZIP」，下载 ZIP 包解压即可。

每阶段操作：
1. 从 `prompts/` 目录找到对应阶段的提示词
2. 复制【执行AI提示词】发给窗口B
3. 等待返回，复制结果
4. 复制【策略AI提示词】+ 结果发给窗口A
5. 等待审查通过，复制下一阶段指令

---

## 下一步

根据你选择的模式，进入 [01-probe.md](01-probe.md) 对应分支开始。
