# Shutong Dev Workflow（书童开发工作流）

> **非程序员的AI辅助开发防偏航完整剧本 v2.0**

[![MIT License](https://img.shields.io/badge/License-MIT-green.svg)](LICENSE)

**核心主张：不确定 → 停 → 问 → 记 → 编 → 答**

---

## 这是什么？

一套专为**不会编程但想用AI开发项目**的用户设计的开发工作流。

通过「策略AI + 执行AI」双窗口协作，把模糊需求拆解为可执行的阶段化操作。每一步都有明确的提示词、审查清单和状态标记。

**你不需要懂代码，只需要会复制粘贴和点确认。**

---

## 快速开始

### 1. 打开网页

双击 `shutong-dev-workflow.html`，用浏览器打开（无需服务器，无需联网）。

### 2. 选择场景

```
🆕 从零新建项目     → 没有代码，从头搭建
➕ 新增功能/模块   → 有代码，要加新功能
🔧 修复现有问题   → 有代码，功能坏了
```

### 3. 打开两个AI窗口

| 窗口 | 角色 | 推荐工具 |
|------|------|---------|
| 窗口A（策略层） | 审方向、给指令 | Kimi / ChatGPT / Claude |
| 窗口B（执行层） | 写代码、跑验证 | Mimo Code / Cursor / Copilot |

### 4. 跟着向导走

- 网页一次只显示**一个步骤**
- 每个提示词卡片标注：**发给谁、时机、预期结果、下一步**
- 点击「**一键复制**」粘贴给AI
- 策略AI审查通过后，点击「**下一步**」继续

## 三种模式

### 🆕 从零新建项目

适用于没有任何代码，从头搭建的场景。

```
初始化 → 设计 → 契约 → 编码 → 验证 → 部署 → 完成
```

- **初始化**：技术选型、目录结构、验收标准
- **编码分4层**：配置层 → 工具层 → 入口层 → 业务层，逐层验证

### ➕ 新增功能/模块

适用于项目已有代码，要加新功能或新模块的场景。

```
探测 → 设计 → 契约 → 编码 → 验证 → 完成
```

- **任意阶段可插入分支**：做到一半想加新需求？点击「➕ 插入新需求」，完成后合并回主流程

### 🔧 修复现有问题

适用于项目已有代码，功能坏了或行为不对的场景。

```
探测 → 设计 → 契约 → 编码 → 验证 → 完成
```

- **诊断导向**：PROBE重点不是摸清全部现状，而是定位哪里坏了

## 核心特性

| 特性 | 说明 |
|------|------|
| **向导式交互** | 一次只显示一个步骤，上一步/下一步流畅推进，不用自己找该复制哪个提示词 |
| **3种独立模式** | 从零新建 / 新增功能 / 修复问题，模式间互不干扰，主题色自动切换（绿/蓝/橙） |
| **双AI纠偏** | 策略AI审方向 + 执行AI写代码，每步策略AI审查通过后才能推进 |
| **阶段冻结** | CONTRACT阶段冻结接口和数据结构，编码阶段禁止超出契约范围的修改 |
| **分支插入** | 主流程任意阶段可插入「新增需求」分支，支持嵌套，完成后合并回主流程 |
| **使用说明卡片** | 每个提示词标注：发给谁、时机、预期结果、下一步，傻瓜式教学 |
| **一键复制** | 点击按钮直接复制提示词到剪贴板，含自动嵌入功能（如文档预审） |
| **文档预审** | 已有MVP文档时，先发给策略AI审查质量（10维度评分），再决定从哪个阶段进入工作流 |
| **检查清单** | 每个阶段底部嵌入人工复核检查点，提醒但不强制 |
| **状态持久化** | localStorage自动保存进度，刷新页面不丢失 |
| **导出/导入** | 支持导出JSON进度文件，随时备份和恢复 |
| **右侧记事本** | 需求/笔记双标签，增删改查，支持导出文本 |
| **异常话术** | 内置卡住话术、违规话术、Git安全速查，一键复制 |
| **键盘快捷键** | → / Enter 下一步，← 上一步 |
| **响应式设计** | 桌面端、平板、手机自适应 |
| **暗色主题** | 护眼暗色界面 |

## 使用流程示例

### 场景：从零新建一个待办事项工具

```
1. 打开 shutong-dev-workflow.html
2. 点击 🆕 从零新建项目
3. 步骤1「初始化」：
   → 复制执行AI提示词 → 粘贴给Mimo → 得到技术选型方案
   → 复制策略AI提示词 → 粘贴给Kimi → 审查通过
   → 勾选检查清单 → 点击「下一步」
4. 步骤2「设计」：设计数据流和骨架顺序
5. 步骤3「契约」：确认接口定义和编码纪律
6. 步骤4「编码」：分4层逐层搭建（配置→工具→入口→业务）
7. 步骤5「验证」：按初始化阶段的验收标准逐项检查
8. 步骤6「部署」：环境检查、依赖安装、上线部署
9. 步骤7「完成」：补全文档、git归档
10. 🎉 项目完成！导出报告
```

### 场景：做到一半想加一个用户登录功能

```
在「编码」步骤时，点击「➕ 插入新需求」
→ 输入分支名称「新增用户登录」
→ 进入新增功能模式，从头走探测→设计→契约→编码→验证→完成
→ 完成后显示「合并计划」，选择回到主流程的「编码」阶段继续
```

### 场景：已有MVP文档，先预审再进工作流

```
1. 点击 🆕 从零新建项目 → 「📄 已有MVP文档」
2. 粘贴你的MVP文档
3. 点击「复制审查提示词」（自动嵌入你的文档内容）
4. 粘贴给策略AI（Kimi），得到10维度评分
5. 根据评分选择：A.直接进设计 / B.补充缺口 / C.重新梳理
6. 进入对应阶段开始工作流
```

## 核心原则

1. **策略AI不碰代码** — 只审查方向和完整性，不写代码
2. **一次只改一个文件** — 防止调用链断裂
3. **每步有状态标记** — 卡住时精准恢复（如 [INIT_DONE]、[CODE_DONE]）
4. **不确定就停** — 任何异常立即停止，等策略AI判断
5. **契约冻结** — CONTRACT阶段后接口不可随意变更，变更需回退到契约阶段
6. **分层搭建** — 从零新建时先配置→再工具→再入口→再业务，被依赖的先创建

## 为什么不用 Cursor / Claude Code 直接做？

| | Cursor Agent | 书童工作流 |
|---|---|---|
| **流程控制** | 连续执行，无阶段冻结 | 每步策略AI审查后才能推进 |
| **需求漂移** | 容易边写边改需求 | CONTRACT阶段冻结接口，编码不可超范围 |
| **双AI审查** | 单AI自问自答 | 策略AI独立审查执行AI输出 |
| **非程序员友好** | 需要理解代码才能判断对错 | 只需复制粘贴和点确认 |
| **状态恢复** | 窗口关闭即丢失上下文 | localStorage持久化，随时恢复 |
| **分支管理** | 无 | 支持插入新需求分支 |

**书童不是替代 Cursor，而是给 Cursor 套上一层防偏航的脚手架。**
